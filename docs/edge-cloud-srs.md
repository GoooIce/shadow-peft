## 1. 引言

### 1.1 目的

明确「产线端侧部署小模型、云端大模型增强」系统的功能边界、性能指标、接口、数据与验收标准，控制开发范围与验收争议。

### 1.2 范围

系统包含：

- 产线端侧推理代理（本地小模型、置信度评估、升级路由、离线队列、反馈采集）；
- 云端增强服务（大模型复核、反馈库、难例导出、适配器注册与灰度）；
- 产线管理控制台；
- 部署、监控、培训与运维文档。

系统不包含：

- 产线设备控制、PLC 写入、MES 改造；
- 大模型基座训练；
- 甲方网络、服务器、GPU、云服务账号的采购与运维；
- 与合同无关的第三方系统对接（如需对接，另行变更）。

### 1.3 术语

见《设计与实施方案》第 2 节。本文使用「端侧」「云端」「升级」「增强」「难例」「适配器」「灰度」等术语，含义一致。

### 1.4 参考

- 《软件开发合作协议》第一、三、四、五条；
- 《产线端云协同推理系统设计与实施方案》；
- 甲方提供的工位清单、任务清单、工艺与质量标准（待提供）。

## 2. 项目概述

### 2.1 业务背景

产线工位需要快速获得工艺、设备、质量、安全类问题的答案。端侧小模型时延低、可离线，但长尾知识不足；云端大模型准确率高，但存在网络时延、成本与数据合规约束。系统通过「本地优先、云端增强、反馈闭环」兼顾三者。

### 2.2 用户角色

| 角色 | 职责 | 主要使用界面 |
| --- | --- | --- |
| 产线操作员 | 提问、采纳/纠正答案 | 工位终端 / 控制台 |
| 工艺工程师 | 维护标准答案、审核难例 | 管理控制台 |
| 质量工程师 | 质检判定复核、阈值确认 | 管理控制台 |
| IT 运维 | 部署、监控、版本与回滚 | 命令行 / 监控系统 |
| 项目管理员 | 权限、审计、数据保留策略 | 管理控制台 / 后台 |

### 2.3 运行环境

- 端侧：Linux x86_64/arm64 工控机或边缘盒子，Python 3.10+；可选 NVIDIA GPU。
- 云端：Linux + NVIDIA GPU（vLLM/SGLang）或 OpenAI 兼容的大模型 API。
- 网络：端侧可出站访问云端 HTTPS；允许完全断网运行。
- 浏览器：Chrome/Edge 最近两个大版本。

### 2.4 约束

- 端侧不得依赖云端完成基本问答；
- 云端调用必须可预算、可熔断、可审计；
- 生产数据上传遵循最小化与脱敏原则；
- 适配器必须可灰度、可回滚；
- 知识产权归属按合同第五条执行。

## 3. 功能需求

优先级：P0 = 验收必须；P1 = 项目期内完成；P2 = 可选/二期。

### FR-01 端侧本地推理（P0）

系统应在端侧加载配置指定的小模型，接收产线问题并返回答案、模型标识、时延与 token 级置信度信号。断网时仍可完成推理。

验收：

- 断开云端后，常规任务连续 100 次请求成功率 100%；
- 返回体包含 `text`、`source=edge`、`confidence`、`latency_ms`、`model_id`；
- 模型路径、设备、dtype、上下文长度可配置。

### FR-02 云端增强（P0）

端侧触发升级时，应把问题、任务类型、端侧草稿、截止时间发往云端；云端返回增强答案、置信度、模型标识与时延。云端提示词应要求复核草稿事实与数值。

验收：

- 升级请求的响应包含 `source=cloud`、`escalated=true`、`escalation_reason`、`edge_text`、`cloud_latency_ms`；
- 云端不可达时，端侧返回本地答案并标记 `degraded=true`，不得抛出未处理异常；
- 云端返回空结果按失败处理。

### FR-03 升级策略（P0）

系统应支持按任务配置升级阈值、强制云端任务、结构化格式校验；支持请求级 `require_cloud`。

验收：

- 置信度低于阈值触发 `low_confidence`；
- 强制任务触发 `task_requires_cloud`；
- 格式不合规触发 `format_invalid`；
- 策略可通过管理接口调整并立即生效；
- 每次决策在 `trace` 中可解释。

### FR-04 置信度评估与标定（P0）

系统应基于 token 对数概率与输出启发式计算 [0,1] 置信度，并支持按任务阈值。项目期应使用产线标注集完成阈值标定，输出 risk–coverage 报告。

验收：

- 给定固定输入与模型，置信度可复现；
- 标定报告包含各任务在候选阈值下的升级率与错误率；
- 阈值经甲方工艺/质量代表确认。

### FR-05 预算、熔断与截止时间（P0）

系统应限制云端调用频率与升级比例；连续失败触发熔断；剩余时延不足时跳过云端。

验收：

- 达到每分钟调用上限后，请求标记 `degraded` 并给出 `budget_max_calls`；
- 升级比例超限给出 `budget_max_ratio`；
- 连续失败达到阈值后熔断，冷却期后自动半开；
- 超时/失败不导致请求挂起。

### FR-06 断网与离线队列（P0）

断网、云端失败或策略跳过时，请求应写入本地持久化队列；网络恢复后自动重放，成功后标记完成，超过重试上限标记 `dead` 并保留现场。

验收：

- 断网期间队列只增不减，推理不受影响；
- 恢复后 5 分钟内清空待同步队列（演示规模）；
- 重放使用原 `request_id`，云端可按幂等键处理；
- 队列文件损坏时跳过坏行，不影响服务启动。

### FR-07 反馈采集（P0）

系统应支持对每次结果提交「采纳」或「纠正」，记录问题、端侧/云端答案、最终答案、置信度、升级原因、适配器版本与备注。

验收：

- 采纳与纠正均写入本地反馈库；
- 云端可用时自动转发；转发失败不影响本地记录；
- 可通过接口按请求 ID 查询或导出。

### FR-08 难例数据集导出（P0）

系统应把未采纳、被纠正或发生过升级的样本导出为 SFT JSONL，按 prompt 去重，包含 system/user/assistant 消息与元数据。

验收：

- 导出文件可被训练脚本直接读取；
- 重复提交同一问题只保留最新答案；
- 空问题/空答案被跳过并计数；
- 导出统计包含总数、导出数、跳过数与任务分布。

### FR-09 适配器训练与发布接口（P1）

系统应提供训练任务接口约定：消费难例数据集，产出适配器目录，登记版本、产物路径、训练指标与备注。具体训练算法可采用 ShadowPEFT、LoRA 或蒸馏，由乙方在项目期确定。

验收：

- 至少完成一次端到端训练（难例导出 → 训练 → 注册）；
- 适配器可在端侧加载并参与推理；
- 训练记录与数据版本可追溯。

### FR-10 灰度与回滚（P1）

系统应按设备稳定哈希分配灰度版本，支持转正与回滚；端侧可拉取当前版本。

验收：

- 同一设备在灰度期间版本稳定，不抖动；
- 转正后新请求使用新版本；
- 回滚在 5 分钟内生效；
- 注册表保留版本历史与操作记录。

### FR-11 管理控制台（P0）

控制台应展示端侧/云端状态、适配器版本、单次推理的决策链路、两侧答案与置信度、反馈入口、核心指标、难例与灰度操作。

验收：

- 1280×720 分辨率首屏可见「执行协同推理」；
- 中文界面，无需安装插件；
- 关键操作有成功/失败提示；
- 页面刷新后指标与实际服务一致。

### FR-12 监控与审计（P1）

系统应提供 Prometheus 指标、健康检查、结构化日志与请求链路；管理操作应留痕。

验收：

- `/metrics` 可被 Prometheus 抓取；
- 指标包含请求数、升级数、云端成功/失败、降级数、时延分位、队列深度；
- 日志可按 `request_id` 关联端侧与云端；
- 审计日志保留期限可配置。

### FR-13 权限与安全（P1）

系统应支持管理接口鉴权、传输加密、租户/工位隔离与敏感字段脱敏；生产环境禁止匿名管理操作。

验收：

- 管理接口未授权返回 401/403；
- 端云通信启用 TLS；
- 日志与反馈中不出现未脱敏的人员信息；
- 安全配置通过甲方评审。

### FR-14 部署与升级（P0）

系统应提供端侧与云端的部署脚本/容器、配置模板、健康检查、启停说明与升级步骤。

验收：

- 在甲方目标环境完成一次全新部署；
- 断网重启后服务自动恢复；
- 升级回滚演练通过。

### FR-15 培训与运维移交（P1）

乙方应提供管理员与操作员培训、运维手册、常见故障处理清单。

验收：

- 完成至少 2 场培训（管理/操作）；
- 甲方人员可独立完成启停、版本发布、回滚、队列排查；
- 移交清单双方签字。

### FR-16 批量离线评测（P1）

系统应支持对固定评测集批量运行端侧/云端/协同三种模式，输出准确率、升级率、时延与成本报告。

验收：

- 评测集 ≥500 条（由甲方确认）；
- 报告可按任务分层；
- 结果可复现（固定 seed/温度）。

## 4. 非功能需求

### NFR-01 性能

| 项目 | 目标 |
| --- | --- |
| 端侧直出 P95 | ≤ 300 ms（目标硬件与模型确定后锁定） |
| 升级请求端到端 P95 | ≤ 3 s |
| 控制台首屏 | ≤ 2 s（局域网） |
| 单端侧并发 | ≥ 5 QPS（0.5B–1.5B 模型） |
| 云端并发 | 按甲方容量，支持水平扩展 |

### NFR-02 可用性

- 端侧本地推理可用性 ≥ 99.9%（不含计划维护）；
- 云端增强可用性 ≥ 99.5%；
- 云端故障不影响端侧基本问答；
- 服务崩溃后自动重启并恢复队列。

### NFR-03 数据一致性

- 反馈与队列采用追加写，进程崩溃不丢已确认写入；
- 队列重放幂等；
- 适配器版本切换原子生效，不出现半版本状态。

### NFR-04 安全

- 传输 TLS 1.2+；
- 管理接口鉴权与最小权限；
- 密钥不落配置文件；
- 依赖组件定期扫描漏洞。

### NFR-05 隐私与合规

- 默认只上传问题与答案文本，不上传原始图像/音频/完整工单；
- 人员、客户、供应商等字段按甲方规则脱敏；
- 数据保留期限可配置，支持按请求删除；
- 跨境传输须经甲方书面同意。

### NFR-06 可维护性

- 配置外置，支持热更新阈值与离线模式；
- 模块边界清晰：协议、路由、后端、反馈、注册表可独立替换；
- 单元测试覆盖核心策略与协议；
- 代码通过静态检查。

### NFR-07 兼容性

- Python 3.10+；
- OpenAI 兼容云端接口；
- Hugging Face decoder-only 模型；
- Linux x86_64/arm64。

### NFR-08 可观测性

- Prometheus 指标；
- 结构化日志含 `request_id`、`edge_id`、`adapter_version`；
- 健康检查区分端侧/云端；
- 支持导出最近请求链路用于排障。

## 5. 接口需求

接口清单与字段见《设计与实施方案》第 6 节。要求：

- 所有接口使用 UTF-8 JSON；
- 错误返回 `{error, detail}` 与合适 HTTP 状态码；
- 推理与反馈接口支持 `request_id` 幂等；
- 版本化路径（`/v1/...`），不兼容变更升版本；
- 云端管理接口与推理接口分离鉴权。

## 6. 数据需求

### 6.1 数据分类

| 类别 | 示例 | 默认处理 |
| --- | --- | --- |
| 工艺参数 | 温度曲线、压力、速度 | 允许上传，按甲方规则脱敏 |
| 设备状态 | 故障码、报警文本 | 允许上传 |
| 质量记录 | 缺陷描述、判定结论 | 允许上传，禁止原始图像默认上传 |
| 人员信息 | 工号、姓名 | 不上传，本地脱敏 |
| 客户/供应商 | 名称、批次 | 不上传或脱敏 |

### 6.2 保留与删除

- 端侧反馈：默认 180 天；
- 云端反馈：默认 365 天；
- 离线队列：完成后保留 30 天；
- 审计日志：默认 365 天；
- 支持按 `request_id` 删除；删除操作留痕。

### 6.3 数据质量

- 训练数据必须来自已确认的反馈或甲方标注；
- 纠正样本需记录纠正人/时间（可脱敏）；
- 导出前做去重、空值过滤与长度限制。

## 7. 验收标准

### 7.1 功能验收

- 所有 P0 需求通过；
- P1 需求完成率 ≥ 90%，未完成项有双方确认的替代方案；
- 关键流程演示：本地直出、低置信度升级、断网降级、恢复同步、反馈闭环、灰度回滚。

### 7.2 性能验收

- 在甲方目标硬件与网络上，用 ≥500 条评测集压测；
- 达到 NFR-01 指标，或双方书面确认的调整值；
- 连续运行 72 小时无内存泄漏、无队列丢失。

### 7.3 试点验收

- 单工位试点 ≥ 2 周；
- 记录准确率、升级率、采纳率、P95 时延、云端成本；
- 无 S1/S2 缺陷；S3 缺陷有整改计划。

### 7.4 文档验收

- 《需求规格说明书》《系统设计说明书》《接口文档》《部署运维手册》《测试报告》《培训材料》齐全；
- 源代码可构建、可部署、注释与配置说明完整；
- 知识产权与移交清单按合同执行。

## 9. 假设与依赖

1. 甲方提供工位清单、任务清单、工艺/质量标准、脱敏规则与评测标注；
2. 甲方提供端侧硬件、网络、云端 GPU/API 账号与运行环境；
3. 甲方指定工艺、质量、IT 接口人，按里程碑参与评审；
4. 云端推理费用、专线费用、产线改造费用不含在开发服务费内（待双方确认）；
5. 真实模型效果依赖基座能力与数据质量，指标以双方确认的评测集为准；
6. 若甲方要求对接 MES/PLC/Andon，按变更流程评估工作量。

## 10. 变更控制

- 需求变更由任一方书面提出，说明范围、影响与优先级；
- 双方评估工期与费用后签署变更单；
- 未签署变更单的口头需求不纳入验收；
- 紧急缺陷修复不受此限，但应在 5 个工作日内补记录。

## 附录 A：任务类型与默认策略（草案）

| 任务类型 | 说明 | 默认策略 |
| --- | --- | --- |
| `process_qa` | 工艺参数问答 | 阈值升级 |
| `fault_diagnosis` | 设备故障诊断 | 阈值升级 |
| `quality_verdict` | 质检判定 | 强制云端 |
| `process_calc` | 参数/指标计算 | 阈值 + 数值格式校验 |

| `general` | 通用 | 阈值升级 |

阈值与强制策略在 M1 标定后由甲方确认。

## 附录 B：指标定义

- **升级率** = 触发云端增强的请求数 / 总请求数；
- **云端成功率** = 云端成功返回数 / 云端尝试数；
- **采纳率** = 反馈为采纳的数量 / 反馈总数；
- **难例率** = 难例数 / 反馈总数；
- **P95 时延** = 端到端请求时延的第 95 百分位；
- **断网可用性** = 断网期间成功返回本地答案的请求数 / 断网期间总请求数。
