ShadowPEFT × LFM2.5 实验结果报告

2026-08-25 · 执行机 GB10(NVIDIA sm_121,121GB 统一内存)· 测试床 LFM2.5-350M-Base(16 层 conv+attention 混合,词表 65,536)· 度量轴 despaced wikitext ppl,上下文携带窗口 512 · 全部数字源自 GB10 runs/ 下的 verdict.json

核心假设首次实测:通过

2-bit 量化把模型打到灾难(ppl 爆炸 2.2 万倍),蒸馏的 shadow 把 99.86% 的差距拉了回来。

规模越大,追得越近

shadow 与全精度的距离:46x → 31x → 25x(230M → 350M → 1.2B,单调改善)。

shadow 是通用追踪器:H1 成立

跨家族 Llama shadow 只落后 22%;与宿主同构的 conv shadow 反而差 107%——"镜像宿主"论被否决。

① 量化损伤与 shadow 恢复(2-bit 三值 + Lloyd,10M tokens 蒸馏)

纵轴为对数刻度 —— 三个数字分别是:全精度基线(绿)、量化后(红)、量化+shadow 蒸馏后(蓝)
全精度 bf16(目标) 2-bit 量化(受损) 量化 + shadow(恢复后)
白话:2-bit 量化后模型基本"失语"(ppl 上百万 = 下一词预测接近乱猜);shadow 蒸馏把它拉回到一千多的量级——拉回了 90–99.9% 的差距,但离全精度(30–50)还差 25–46 倍。规模越大,拉回后离全精度越近,这支持"边缘部署更大量化模型 + 廉价 shadow"的叙事。

② 8-bit 档:零损伤验证(通过)

近无损的 8-bit 量化基座上,挂上蒸馏的 shadow 后模型没有变差,还略赚 1.8%——shadow 不伤干净基座,这是它作为"外挂补偿器"的资格证明。

③ 异构 shadow 消融:shadow 到底需要"长得像"宿主吗?

同一 2-bit 受损基座、同一教师数据、有效参数对齐(≈35M),只换 shadow 的架构 · 各 5M tokens
白话:注意力占比越高恢复越好(conv 纯 3825 → 混合 2518 → 纯 attention 1846);跨家族的 Llama shadow(2256)只落后基准 22%——shadow 学到的是"通用状态修正",不依赖和宿主同架构。意外 纯 conv shadow(3-token 记忆)没有像预期那样崩溃,但仍差 107% 且无法做缓存解码,重映射默认值保留。

④ 收敛轨迹(350M,蒸馏过程中的 ppl)

10M tokens 时仍在缓慢下降但收益递减(每 250 步约 −2%);1,652 是 20 窗口径终评,图中轨迹为 8 窗口径。

⑤ 过程备忘(怎样拿到这些数字的)

  • 📏 度量轴先行(阶段 0):LFM 分词器对 wikitext 几乎不 OOD(1.25x,vs Gemma 的 30–50x);BOS 零风险;上下文窗口必须(冷窗口 ppl 虚高 3.06x);重跑方差 0。轴值 Base = 36.77,同轴 it 档 = 345(故量化轴用 Base,it 档留给下游与实验②)。
  • 🧪 P0 挂载冒烟 6/6:conv+attention 混合层挂 shadow、缓存解码、swap 位级一致、tied embedding 训练、三方案 PTQ 往返。
  • 🔧 修掉三个库级 bug:① 空混合缓存不能喂给 backbone(LFM2 抛 get_seq_length 错)→ prefill 传 None 并收养返回缓存;② 隐式 shadow 切出纯 conv 前缀 → 重映射为 attention 层;③ LFM tokenizer(64,400)< 词表(65,536),裁词越界 → trainer 禁用裁词。
  • ⚡ 速度:教师数据自采样 11k tok/s;350M 蒸馏 6.5k tok/s(5M tokens ≈ 13 分钟);全部实验总 GPU 时间 ≈ 3 小时(一台桌面级 GB10)。
  • 📚 口径:LLM-QAT 式自采样教师(教师=全精度自模型,分布与评测一致);恢复率/绝对距离双口径并报;数据文件在 GB10 runs/exp1/ 与 runs/exp4/verdict.json,spec 与决策记录在 .scratch/experiment-redesign/。
