五条实验线,讲给所有人听 —— ShadowPEFT 实验总结合话版

2026-08-25 · 实验对象:LFM2.5 家族的三个小模型(230M / 350M / 1.2B 参数)· 实验机器:两台 GB10(桌面大小的强算力盒子)· 白话版,专业词首次出现都在括号里解释

这个项目在研究什么?(两分钟版)

大模型太大太贵,想把它塞进手机、机器人这类小设备,常见办法是量化(把模型里的数字四舍五入成更省内存的格式,比如每个数只用 2 个比特而不是 16 个)——但压得太狠模型会"失语"。 我们的核心想法叫 ShadowPEFT:在压坏的模型旁边挂一个小小的影子模型(shadow,一种轻型"修补网络",一边跟着大模型跑、一边学会纠正它犯的错), 而且这个修补器可以像 U 盘一样热插拔、随时换成另一个领域的修补器。整套故事的目标场景:边缘设备上跑"压缩过的大模型 + 廉价可插拔的影子修补器"。

围绕这个想法我们排了五条实验线,逐一回答:① 影子能把损伤修回来多少?② 影子能不能顺便帮大模型"打草稿"提速?③ 一个叫 recirculation 的外部技巧能不能和影子叠加?④ 影子必须长得像宿主吗?⑤ 给打草稿的影子"开小灶偷看答案"值不值?

① 量化恢复 通过

2 比特压缩把模型打到接近乱猜,影子修补器拉回 90–99.9% 的差距;模型越大追得越近(距离 46 倍→25 倍)。

② 打草稿提速 质量过 / 提速不及格

草稿平均采纳数 τ 最高 4.66(满分 9);实际提速最好 1.02 倍(及格线 1.4 倍)——这台机器的物理特性封顶,白话终报。

③ Recirculation 循环注入 未定

48 种配置无一有效(最好只改善 0.4%,及格线 2%);还差一个"照抄论文"的复现实验来定论是"我们做错了"还是"这招本来就不适用于这类模型"。

④ 影子需要长得像宿主吗 不需要

换用别家架构(Llama)的影子只落后 22%;反倒是模仿宿主层型的差 107%——影子是通用修补器,不挑宿主。

⑤ 给草稿器"偷看答案" 不值

四种条件从弱到强:1.5 / 3.0 / 3.5 / 9——"偷看"(KV 注入,让草稿模型实时看到大模型的中间记忆)反而比不偷看差 14%。

① 量化恢复:影子能把"失语"的模型修回来多少?

详细图表见①④深挖白话版

用 ppl(困惑度,衡量模型对一段文字有多"出乎意料",越低越好;几十算正常,上百万等于接近乱猜)打分: 2 比特压缩后三个模型的 ppl 分别爆到 7 万、118 万、7 千;挂上影子修补器(用蒸馏训练——让小修补器模仿原版大模型的"学生式"学习法)后拉回到 1,848 / 1,652 / 743——差距的 90–99.9% 被拉回来了。 最亮的发现:模型越大,修补后离原版越近(46 倍 → 31 倍 → 25 倍,一路缩小),支持"边缘设备装更大量的压缩模型 + 廉价影子"的路线。 另外在几乎无损的 8 比特压缩上,影子不但不添乱还小赚 1.8%——"外挂修补器"的资格证明。

② 打草稿提速:质量赢,速度输,输得明明白白

完整故事见白话终报(三轮进攻 + 理论推算)

投机解码(小模型先猜几个词片——token,模型处理文字的最小单位,约半个到一个词——大模型一次检查完)在我们这台机器上: 草稿质量很好(τ,平均每轮真正采纳的词片数,最高 4.66,达到理想上限 oracle 的 52%;oracle 指假设草稿每次都猜中的完美假想情形,k=8 时每轮最多采纳 9 个,是理论天花板); 但实际耗时只快到 1.02 倍(及格线 1.4 倍)。我们试了逐字打草稿、一次猜一整块(两种知名结构 DSpark 式/DFlash2 式)、以及理论推算,三条路都到不了 1.4 倍—— 根因是这台机器每跑一步都要把模型参数整个读一遍内存,小模型(4.4 毫秒)只比大模型(13.2 毫秒)快 3 倍,而草稿每轮只值约 3 个词片,这笔账凑不平。 意外的净收获:如果云端服务是"无状态"的(每生成一个词片都要网络往返一次),我们的方法每轮只往返一次、带回约 3 个词片——50 毫秒延迟下快 2.1 倍,这是一个文献里没人系统做过的比较角度。

③ Recirculation 循环注入:外来技巧,水土不服(暂记"未定")

Recirculation(循环注入,一篇论文提出的技巧:把神经网络深层的计算结果搬运回浅层再利用,号称不训练就能让模型变好 8.5%)据说只在特定结构的模型(Gemma 系列)上灵。 我们的模型是另一种结构(卷积+注意力混合),论文配方在这里48 种配置试了个遍,最好只改善 0.4%(及格线 2%),而且"卷积层"当搬运源头时反而灾难性变差(最多差 27%)。 我们还做了个原创尝试:把这套搬运技巧用在影子模型自己的计算流上——结果"能共存但零增益"。 按事先定好的判定规则:要下"这招不适用"的结论,必须先原样复现出论文在 Gemma 上的效果(证明不是我们做错了)——这个复现实验是下一仗。

④ 影子需要长得像宿主吗?不需要——这是个好消息

详细图表见①④深挖白话版

同一个压坏的基座,换四种不同长相的影子修补器(参数量对齐):纯注意力(attention,能回看前文任意位置的记忆层)最好; 卷积(conv,只记得住最近 3 个词片的短时记忆层)最差(差 107%);混合的居中。 最关键的一格:用别家公司架构的 Llama 影子(同样是纯注意力),只落后基准 22%——"影子必须镜像宿主"的假说被否决,"影子是通用修补器"的假说成立。 这意味着影子可以挑最便宜、最通用的架构来做,工程自由度大了很多。

⑤ 给草稿器"偷看答案":实测不值,反而强化了我们的部署故事

打草稿实验里有个诱惑:让草稿模型实时偷看大模型的中间计算结果(叫 KV 注入,KV 指大模型阅读前文时记下的笔记),理论上草稿会猜得更准。 实测四种条件从弱到强:从零训练 1.5 → 偷看 3.0 → 不偷看 3.5 → 满分 9——偷看反而比不偷看差 14%。 机理也查清了:训练时草稿随时能偷看,考试(实际部署)时新词片来不及偷看,依赖养成又断供,发挥反而失常。 这个"负结果"恰恰强化了我们的边缘部署故事:部署时不需要向云端上传大模型的中间记忆(兆级数据),一个廉价独立的小草稿器就够了。
