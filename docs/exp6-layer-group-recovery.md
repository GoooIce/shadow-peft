## Agent Brief

**Category:** enhancement
**Summary:** 恢复训练新增「贪心逐组层调度」：把端到端蒸馏拆成层组贪心训练 + 端到端收尾，与纯端到端基线在等 token 预算下由 GB10 实验结果裁决。

**Current behavior:**
恢复训练（`shadow_lab` 的 `train_shadow`）是端到端的：教师一次性给出 logits/隐态，学生（量化基座 + 影子适配器）整体前向，单一损失 backward，梯度流过整条注入/更新链。注入与更新模块的参数本来就按层参数化（`ShadowInjectionModel.injection_downs[layer_idx]`、`ShadowUpdateModel.update_gates[layer_idx]`），但训练循环没有任何按层/按组调度的能力：激活内存随全链增长（12B 级才被迫开 gradient checkpointing），也无法按层归因恢复量。

设计必须尊重的架构事实：

- 影子骨干每序列只跑一次产出初始影子态；**单一演化影子态被所有基座层共用**（层 k 前注入 `injection[k]`，层 k 后更新 `update[k]`）。
- `ShadowUpdate` 的门与变换只吃基座隐态 h（`s' = s + g(h)·(T(h) − s)`）：给定一条 h 轨迹，影子态链可离线前向推出；重算开销极小（LN + 两个小 MLP/层）。
- **局部梯度盲区**：对齐第 k 层教师隐态的局部损失只给 `injection[k]` 梯度；`update[k]` 在第 k 层之后才执行，局部信号为零——不显式处理的话，逐层训完后 update 模块全留在初始化。

**Desired behavior:**

`train_shadow` 支持层调度模式，与现有端到端模式共存于同一入口：

1. **逐组贪心（主臂）**：按层序把基座层切成大小为 `group_size`（默认 4–8）的组；组前缀在 no_grad 下推进并缓存组边界的 `(基座隐态 h, 影子态 s)`；组内联合训练该组的注入/更新模块，目标为教师对应层的归一化隐态 MSE（复用 `_hidden_mse_loss` 的口径）。
2. **逐层贪心（对照臂）**：`group_size=1` 的特例；局部阶段只训注入。
3. **端到端收尾（polish）**：每个分层臂以短端到端阶段收尾（预算占比默认 20–30%），负责训 update 模块与全局一致性；KL/CE 损失只活在收尾阶段，分层阶段用隐态 MSE。
4. 影子态盲区的两种处理（缓存链冻结 vs 组窗内重算影子链让梯度流过 `update[k-1]`）做成配置开关，默认组窗重算。

**实验裁决协议（本票的核心验收）：** 在 GB10 双机上跑等总 token 预算的三臂（端到端基线 / 逐层贪心+收尾 / 逐组贪心+收尾），同教师数据池、同 seed 策略、同评测轴（挽回率 + `eval_kld`；RL/instruct 模型走留出判定轴 axis2 口径）。产出对比表：挽回率、每 token 平均 KL、墙钟、峰值激活内存。裁决规则：等预算下挽回率不低于基线、且墙钟或峰值内存显著降低 → 分层调度立住；否则记录负结果并归因（层间误差累积 vs update 盲区 vs 预算切分）。

**Key interfaces:**

- `TrainConfig` — 新增调度字段（建议形如 `layer_schedule: "end2end" | "per_layer" | "groups"`、`group_size: int`、`polish_token_frac: float`）；`layer_schedule="end2end"` 必须与现状行为逐位等价。
- `ShadowPeftModel` — 需要一个层驱动接缝：能从缓存的 `(h, s)` 边界状态执行单层或单组（前缀 no_grad），而不是只能整体 `forward`。行为契约：边界张量必须 detach，组外可训参数 backward 后 `grad is None`。
- `train_shadow` — 保持单一入口；`TrainReport`/`summary.json` 增补调度字段与逐层归因表，供裁决脚本消费。
- 逐层归因（新测量轴）——输出每层归一化隐态 MSE 的 quant-only vs quant+shadow 对照表，回答「量化损伤集中在哪些层」。
- 检查点格式 — 调度是训练期概念：`shadow_adapter.safetensors` 的结构与保存/加载路径不变。

**Acceptance criteria:**

- [x] `layer_schedule="end2end"` 与改动前 `train_shadow` 在同 seed 小模型冒烟下损失轨迹一致（回归保护：现有 lab 套件 94 passed 不变，end2end 走原代码分支）
- [x] 单元测试（Mac 级）：贪心调度下边界张量 detached、组外参数无梯度、局部损失对当前层 `update` 零梯度（`tests/lab/test_layerwise.py`，含 ZeroInit 事实）
- [x] 单元测试：组窗影子链重算开启时 `update` 模块在分层阶段确实收到梯度；关闭时留给 polish 阶段，训练结束时 update 参数偏离初始化
- [x] GB10 三臂等预算 campaign 跑完，summary.json 含挽回率/KLD/墙钟/峰值内存对比 + 逐层归因表
- [x] 手动 DDP 冒烟仍通过（贪心模式与 `_sync_grads` 的 None-grad 过滤兼容；`tests/lab/test_trainer_dist.py` 在套件内通过）
- [x] 适配器 save→load 往返在新调度产物上不变（现有 loader 测试直接覆盖）

**Out of scope:**

- 不改影子架构本身（注入/更新的数学、`alpha` 语义、模块参数化）
- 不新增量化方案或 backbone tier；w8a8 臂遵守联合校准铁律（贪心变体保持真实输入分布，不破坏该前提）

## 裁决结果（2026-08-31，GB10 双机，10M token 等预算）

testbed：LFM2.5-2.6B-Base × w4a16（fake-quant），L1_4x 影子锚（279,013,504 可训参数），
教师池 `teacher_2p6b_base.jsonl`，`ce_kl`，axis = despaced wikitext ctx=512 chunks=20。
预检门实测：重放奇偶 **max_abs_diff = 0.000e+00**（捕获帧逐位复现 LFM2.5 自身前向，
含按 `layer_types` 的逐层掩码选择）。2.6B 共 30 层 → G4 切 8 组（7×4+1×1），G1 逐层 29 组。

| 轴 | E2E（锚） | G4（逐组贪心+polish） | G1（逐层贪心+polish） |
| --- | --- | --- | --- |
| 挽回率 recovery | 0.6574 | **0.7148** | 0.6414 |
| ppl_shadow | 10.7677 | **10.7143** | 10.7826 |
| KLD(bf16‖quant+shadow) | 0.0918 | 0.0923 | **0.0913** |
| 墙钟 train_seconds | 5702.8 | 3770.0（−34%） | **3544.6（−38%）** |
| 峰值内存 peak_mem_gb | **48.4** | 49.5 | 49.5 |
| 阶段切分 | — | greedy 2040.8s / polish 1723.5s | greedy 1826.2s / polish 1713.0s |

**最终裁决：G4（逐组贪心）立住**——等预算下挽回率高出锚臂 5.7 个百分点且墙钟快 34%，
内存持平（+1GB 为边界缓存代价）；KLD 轴三臂打平（0.0913–0.0923，均自 0.1012 收敛，
彼此差异在轴噪声内）。**G1（逐层）不满足严格裁决规则**：挽回率 0.6414 低于锚
（−1.6pp），墙钟虽最快（−38%）但质量不占优——组窗切到 1 后层间误差累积 / update
饥饿时间变长，块大小 trade-off 落在「组」不在「层」。结论：**逐组是正确粒度，
group_size=4 为推荐起点**。

逐层归因（G4，init→final 每层归一化隐态 MSE）：**全 30 层一致改善**，中段（第 6–20 层）
绝对收益最大；唯一例外是最后一层（0.0397→0.0512 恶化）——组末层 update 的梯度盲区
常驻层，其注入只靠 polish 的远距梯度与 post-norm 目标对齐。后续可选优化：末组单独
加大 polish 配额，或末层注入改用 pre-norm 目标。

过程记录：首轮 G4 死于 LFM2 的 final-norm 命名（`embedding_norm`，预检门拦截，符合设计）；
修复后第二轮 G4 在贪心→polish 边界触发 spike-guard 死循环回滚（损失尺度从 MSE ~0.05
切到 CE ~4，中位数跨阶段失效）——阶段边界重置 `recent_losses` 后第三轮全通过。
教训已固化在 `tests/lab/test_layerwise.py` 与 trainer 注释里。

verdict 与检查点：GB10 `runs/exp6/{E2E,G4,G1}/`，本地备份 `runs-local/exp6/`。

## 预算外推 + 数据池裁决（2026-09-01 追加）

### 旧池（teacher_2p6b_base.jsonl，~10M token，有放回采样）跨预算

| 臂 | 10M | 30M | 100M（≈10× 重复） |
| --- | --- | --- | --- |
| E2E | 0.6574 | 0.6415 | **0.4904（塌方）** |
| G1 逐层 | 0.6414 | 0.7250 | 0.6414 |
| G4 逐组 | 0.7148 | **0.7395（全程峰值）** | 0.6240 |

- **10M 的排序不保真**：G1 从垫底（10M 0.6414）到 30M 反超（0.7250）——预算放大后贪心
  调度的 token 效率优势持续放大，而锚臂 10M→30M 即饱和（0.657→0.642）。
- **旧池撑不起 100M**：三个调度全部回落，锚臂塌得最狠（0.49）。旁证：E2E-100M 的 KLD
  反而是全场最好（0.0882）——贴教师贴到记住池子，代价是 wikitext ppl 崩；贪心臂更扛
  （分组/逐层的局部目标天然限制了记忆容量）。
- 墙钟规律跨预算稳定：贪心阶段 ~3,400–4,000 tok/s vs 端到端 ~1,755 tok/s；G4-100M
  37,542s vs E2E-100M 80,530s（**省 53%**）；峰值内存三臂持平（48.4 / 49.5GB）。

### 新池重跑（teacher_2p6b_base_100m.jsonl，195,472 行 ≈ 98.8M token，双机 seed 302/303 各半生成，md5 `3c8799b3…` 双机一致）

目的：分离「预算效应」与「数据重复效应」——100M 预算 × 全新无重复数据，三臂
（`runs/exp6_100m_fresh/{E2E,G4,G1}`）。结果：

| 臂 | 100M 旧池 | 100M 新池 | 墙钟（新池） |
| --- | --- | --- | --- |
| E2E | 0.4904 | 0.6614 | 58,176s |
| G4 逐组 | 0.6240 | 0.6731 | 37,587s（−35%） |
| G1 逐层 | 0.6414 | **0.7109** | **35,482s（−39%）** |

### 最终跨预算 × 跨池裁决表（挽回率）

| 臂 | 10M 旧池 | 30M 旧池 | 100M 旧池 | 100M 新池 |
| --- | --- | --- | --- | --- |
| E2E | 0.6574 | 0.6415 | 0.4904 | 0.6614 |
| G1 逐层 | 0.6414 | 0.7250 | 0.6414 | **0.7109** |
| G4 逐组 | 0.7148 | **0.7395** | 0.6240 | 0.6731 |

**结论（12 臂、约 90 GPU 时）：**

1. **分层调度全面胜出**：所有预算×池组合下，贪心调度质量 ≥ 端到端且墙钟 −35%~−49%。
2. **粒度排名随预算翻转**：≤30M 时逐组（G4）占优（联合组内监督在小预算下更高效）；
   100M 大池时逐层（G1）反超（0.7109 vs 0.6731）——每层分到的 token 密度
   （100M/29 层）超过组预算效应。实用配方：预算 <30M 用 G4，≥100M 配大池用 G1。
3. **端到端天花板 ~0.66**：新旧池、任意预算，E2E 从未突破——恢复上限被联合优化
   本身卡住，不是数据或预算。
4. **数据池是 100M 的第一约束**：旧池 10× 重复令三臂全塌（E2E 最惨 −17pp），
   新池全面恢复；新池 E2E 也只回到自己的 10M 水平。**全场最优仍是 G4-30M 0.7395**
   （旧池 3× 重复——适度重复在该预算下像正则）。
5. KLD 轴与 ppl 轴在过拟合区脱钩（旧池 100M：KLD 最好的 E2E ppl 最差）——轴间
   交叉验证是必要的。

verdict 全备份：本地 `runs-local/exp6/{E2E,G4,G1}`、`runs-local/exp6_30m/`、
`runs-local/exp6_100m/`、`runs-local/exp6_100m_fresh/`。
