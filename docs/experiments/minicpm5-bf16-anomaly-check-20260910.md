# MiniCPM5-2B NVFP4 W4A4：v3 池上 "BF16 在 hard logic/ordering 反而更差" 的成因核查

- 上游：`pools-v3`（85,815 题生成池 + q0/BF16 双参照臂）、`taskset`（§1.2 题面口径 / §4.1 评分协议）、`confirm-power`（§1.2 stratum 重设计）
- 机器：本地 Mac（纯标准库：join / 分类 / 统计 / gold 复算）＋ `gooo`（GB10，**仅 289 s GPU**，两段探针）；`goooinext` 未触碰（按其上的无关 sglang 作业要求）
- 工作树：`/tmp/shadow-peft-minicpm5-sanity`，分支 `codex/wayfinder-minicpm5-sanity`（从 `main` 的 `86d337b` 起）；主工作区只读
- 脚本：`scripts/minicpm5/anomaly_{join,analyze,gold_check,criterion,probe_build,probe}.py`
- 产物：`docs/experiments/artifacts/minicpm5-bf16-anomaly-check-20260910/`
- 判定：**负 gap 不是能力差、不是 gold 缺陷，也不是题干歧义**——它是 **TF/GEN 判据在冻结续写前缀 `Answer:` 上测到的一种"提前结束回合"行为**（模型第一个 token 就是 `<|im_end|>`），该行为**可精确复现**、**与题面长度无关**、**去掉 9 个字符的 `Answer:` 后缀即整体消失（65.4% → 0.0%）**。在"两个臂都真的作答"的子集上，BF16 在 `logic/hard` **反超 q0 +11.1 个点**、`ordering/hard` 打平（−0.5 点）。**全池 +10.72 的量化代价结论成立且偏保守**（剔除两档后 +14.78、剔除"未作答"题后 +14.24），但**逐 stratum 的 −10.3 / −6.5 是判据产物，不能作为"hard 档 BF16 更差"的证据**；平衡池上的 −35.0 / −29.8（T4）更是"按 q0 对错各半"的抽样把这种错位放大的结果。

## 0. 一句话结论

把 v3 的 85,815 题按**题干**把第一版（23,708 题）与 delta（62,107 题）两段分数 join 回来后（`tf_acc` 复算与清单逐位一致：q0 `0.3853871700751617`、BF16 `0.49258288178057477`），逐题核查发现：**BF16 在 `logic/hard`/`ordering/hard` 的失败里有 76%/59% 是"根本没作答"**（GEN 臂第一个 token 就是 `<|im_end|>` = 130073；`gen_text` 全空、`finish=stop`），而不是答错；"答案正确但格式跑偏"（假设 2 的字面形式）**只有 1/1262 与 2/1001 条（0.08% / 0.20%）**。在**两臂都作答**的子集上 BF16 在 `logic/hard` **+11.13 点**（n=2,202）、`ordering/hard` **−0.47 点**（n=4,478，不显著）。逐条复算 gold 与题面：15,206 条里 **0 条**"题面与验证器规格不一致"、**0 条** gold 与独立求值器不一致、`ordering/hard` **8,585/8,585** 的关系集都唯一确定全序（无歧义、无矛盾）——**gold/验证器无缺陷**（假设 3 被排除）。子模式上，`logic/hard` 的负 gap **90% 集中在"gold=4"这一个子模式**（−51.7 点 / n=1,182，占 −10.26 中的 −9.25），成因是 **q0 的答案先验偏向 4**（对每个 gold 都答 4 的概率 38–51%）而 BF16 偏向 2/3；`ordering/hard` 两个 rank 子模式均匀（−6.7 / −6.3），无集中。计量上：**"未作答"轴在 stratum 内部的杠杆 ≈0.17 点/百分点**（`logic/hard` 10.3 点 ÷ 61.2 个百分点的臂间差、`ordering/hard` 6.5 ÷ 38.9），它把**池级**数字压低 **3.5 个点（生成池口径 +10.72 → +14.24）/ 3.9 个点（平衡池口径 +8.59 → +12.44）**；两档恰好是 dev 池 480 题里的 **64 题 = 13.3%**，所以对**每候选 dev fitness**（搜索真正用来排序的信号，δ_min 6.7 点）的潜在杠杆可达 **13 个点**——这条轴必须登记为干扰轴，而不是可以忽略的噪声。

## 1. 方法与可复算

### 1.1 分数 join（只做数据搬运，未重跑任何模型）

v3 的 85,815 题分数是"第一版 23,708 题全评 + 62,107 题 delta 新评"两段拼起来的（`make_delta.py` / `merge_pool_scores.py` 的口径：**同一题干 = 同一道题**），而 `pool_v3_*_full.jsonl` 本身未入库。本票在本地按完全相同的规则重建（`anomaly_join.py`），并把它当**正确性自检**：

| 量 | 重建值 | 清单值 | 一致 |
| --- | ---: | ---: | --- |
| 题数 | 85,815 | 85,815 | ✓ |
| 题干复用 / delta | 23,708 / 62,107 | 23,708 / 62,107 | ✓ |
| 跨 stratum 移动的题 | 1 | 1 | ✓ |
| q0 `tf_acc` | `0.3853871700751617` | 同 | ✓ |
| BF16 `tf_acc` | `0.49258288178057477` | 同 | ✓ |
| 丢失分数的题 | 0 | — | ✓ |

另外两条**独立**的旁证：(a) 逐题 `n_prompt_tokens` 在**两臂之间完全相同**（85,815/85,815）——两臂各自加载自己的 tokenizer，但 tokenization 一致；(b) 两个模型目录的 `chat_template.jinja` **逐字节相同**（`diff` 为空）——所以"BF16 与 q0 拿到的 prompt 不同"这一混淆因素被排除。

### 1.2 判据与字段（逐字沿用冻结口径）

`enable_thinking=False`、助手侧固定前缀 `Answer:`、gold 文本 = `" " + answer`；TF = `SamplingParams(prompt_logprobs=1, max_tokens=1, temperature=0)`，item 正确 = 全部 gold token 的 argmax 命中；GEN = 贪心 `max_tokens=24`、`stop_token_ids=[1, 130073]`、同一 `taskset_lib.verify` 判定；prefix cache 关。**本票新增的解读字段只有两个**（都不是新测的）：`gen_n_tokens == 1`（GEN 臂第一个 token 就是 stop token，即"没作答"）与 `gen_text`（逐条文本）。分类时用 GEN 臂当"模型到底知不知道答案"的仲裁者。

### 1.3 GPU 探针（§7）协议

同一协议、只加两件记录：**原始输出 token id** 与**prompt 变体**。变体在本地构造、写成条目文件（不修改任何池文件）：`--quantization=`（BF16）/ `--quantization compressed-tensors`（q0）、`--linear-backend cutlass`、`VLLM_WORKER_MULTIPROC_METHOD=spawn`、清 flashinfer lock、载入前后均无遗留进程。1600 题 × 2 臂，两次运行共 **289 s**。

在 BF16 输掉的 1,262 条（`logic/hard`）里，`tf_token_hits` **只可能是 0 或 1**（gold 恒 2 token，逐条明细可复算）：**303 条**是"起手对了（空格命中）、第二个 token 是错数字"（真答错）；**958 条**是"全空"——其中 **593 条**连起手都没有（`hits=0`）、**365 条**吐了空格就结束（`hits=1`）；**只有 1 条**是"答案对、续写跑偏"。逐条看，**没有任何一条是"答对之后再啰嗦/再展开"**。

## 5. T4 gold / 验证器核查（**独立求值器**，假设 3）

对 `logic/hard` + `ordering/hard` + `pct/easy` 的**全部 15,206 条**逐条做三件事（`anomaly_gold_check.py`；布尔公式用本票自带的下推解析器求值，**不复用** `taskset_lib.eval_bool_expr`，避免"生成器与验证器共享 bug 互相掩盖"）：

| 检查 | `logic/hard` | `ordering/hard` | `pct/easy` |
| --- | ---: | ---: | ---: |
| 题面文本 ↔ 验证器规格不一致 | **0** / 6,621 | **0** / 8,585 | **0** / 3,368 |
| gold 与独立复算不一致 | **0**（计数复算） | **0**（拓扑序取第 k 高） | **0** |
| 关系集多解（不唯一确定） | — | **0** | — |
| 关系集自相矛盾 | — | **0** | — |
| 题干含重复关系句（仅冗余，不影响唯一性） | — | 5,750（67.0%） | — |

- **结论：假设 3 被排除。**题面确定 gold、gold 唯一、验证器与题面同源且一致；`ordering/hard` 的重复句子（生成器有放回采样关系的副作用）只是行文冗余，**不影响唯一性**（8,585/8,585 都只有一个拓扑序）——因此它也不是"BF16 拒答"的理由（同题下 q0 会答 "Cannot be determined"，BF16 直接空输出，两臂行为不同但都不是题目缺陷）。
- 这一条也很重要：它排除了"BF16 是因为题目本身有毛病才不答"的可能性。

## 7. T6 子模式分解

子模式以 `meta` 派生（`logic/hard` 全是 `n_formulas=5`，按 gold 值分；`ordering/hard` 全是 `n_names=5`，按被问的名次分；`pct/easy` 按 gold 量级分——与清单 `sub_mode_mix` 的 `"-"` 标签并存，不冲突）。

| `logic/hard` 子模式 | n | q0 TF | BF16 TF | gap | BF16 未作答 | 该子模式对 −10.26 的贡献 |

| rank=2 | 4,295 | 0.205 | 0.138 | −0.067 | 0.439 |
| rank=3 | 4,290 | 0.158 | 0.095 | −0.063 | 0.475 |

- **假设 4 在 `logic/hard` 上部分成立、并且比"子模式"更具体**：负 gap 的 **90% 来自 `gold=4` 一个子模式**（−9.25 / −10.26）。成因不是"这个子模式的题有毛病"（§5 已排除 gold 缺陷），而是**两个模型的答案先验错位**：q0 无论 gold 是多少都偏向答 4（对 gold=1/2/3/4 答"4"的概率分别 0.38/0.42/0.46/0.51），而 `gold=4` 的题目恰好多（1,182 条，17.9%），于是 q0 在这块"押中"最多（0.558）；BF16 作答时 **88.9%（2,033/2,288）答 2 或 3、只有 3.0%（68 条）答 4**，在 `gold=4` 上只有 0.041。（两臂的作答分布：BF16 = {'2':930,'3':1103,'0':144,'4':68,'1':26,'5':17}；q0 = {'4':2923,'3':1528,'2':781,'0':476,'5':343,'1':285}——**q0 有 46.1% 的作答是"4"**。）
- **`ordering/hard` 没有子模式集中**（−6.7 / −6.3 均匀），它的负 gap 就是"BF16 少答 46% 的题"。
- 一个必须同读的底数：`logic/hard` 整档对两臂都接近**地板**——"恒定答 4"策略的期望分 = P(gold=4) = 0.179，均匀乱猜 = 1/6 = 0.167，q0 实测 0.234、BF16 实测 0.131（BF16 低于恒定答 4，因为它 65% 不答）。所以这一档的"能力差"本身就在噪声/先验的量级上，用它的逐 stratum 数字做门限或损失整形是危险的。

## 8. T7 因果探针（`gooo`，289 s GPU）

## 9. T8 判据/分层变化下 `+10.72` 还剩多少

| 口径 | 全池 | `logic` 家族 | `ordering` 家族 | `logic/hard` | `ordering/hard` |
| --- | ---: | ---: | ---: | ---: | ---: |
| **A 冻结原样**（生成池，item 加权） | **+10.72** | +5.68 | +0.82 | **−10.26** | **−6.48** |
| B 只保留"两臂都作答"的题 | **+14.24**（n=75,545） | +15.53 | +8.31 | **+11.13**（n=2,202） | −0.47（n=4,478） |
| C 剔除两个 hard 档（其余 13 档） | **+14.78** | — | — | — | — |
| D 平衡池重加权（= confirm 口径） | **+8.48**（清单 T4；本票复算 +8.59，逐 stratum 与 T4 差 ≤0.012） | −6.7 | −4.1 | **−35.0** | **−29.8** |
| E = D 且只保留"两臂都作答"的题 | **+12.44**（本票复算） | — | — | −8.79 | −15.89 |

- **总账成立且偏保守**：把"未作答"从分母里拿掉，或者把两档整体剔除，**代价都变大**（+10.72 → +14.24 / +14.78）。所以"BF16 比 4-bit 好 ≈10.7 个点"这个**结论方向与量级可以原样保留**；受污染的只有**逐 stratum 的负 gap 叙事**。
- **平衡池口径（D）为什么把负 gap 放大**：confirm 池按"q0 对/错各半"取题，于是**它的 stratum 内 q0 恒为 0.5000**，而另一臂的分数就是它在这个"按 q0 挑过的"子集上的准确率。代数上 `gap_balanced = ½·P(bf16 对|q0 对) + ½·P(bf16 对|q0 错) − 0.5`；`ordering/hard` 的 `P(bf16 对|q0 对)=0.357`、`P(bf16 对|q0 错)=0.063` → 平衡后 0.210，于是 −29.8。**这两个条件概率的差（对称性）取决于"两臂的错误是否在同一批题上"**，而 §7 显示两臂的错误由**答案先验**（q0 偏 4、BF16 偏 2/3；名字先验不同）决定——所以 confirm 上的逐 stratum 负 gap 是**抽样设计 × 先验错位**的乘积，不是独立的第二份证据。v3 笔记 §2 观察 3 已经预感到了这一点（"平衡池上的代价与池外不同"），本票把它定量化了。
- **把伪影剥掉后平衡池还剩多少**（同一重加权、只保留两臂都作答的题）：`logic/hard` −0.3504 → **−0.0879**；`ordering/hard` −0.2898 → **−0.1589**；两档对 15 档均值的拖累 −4.27 点 → **−1.65 点**；全池 strata-equal 均值 **+8.59 → +12.44**。也就是说：平衡池口径下"未作答"占 **3.85 个点**，另有 **1.65 个点**是这两档**真的**（在 q0 挑选过的子集上）不如 q0——与本票 §7 的先验错位一致，必须与伪影分开记账。
- **杠杆（要写进 300 代 run 的风险账）**：`logic/hard` 上"未作答"每变 1 个百分点 ≈ 0.17 个 stratum 点（10.3 / 61.2），`ordering/hard` ≈ 0.17（6.5 / 38.9）。放进池子看：两档合计只贡献生成池 +10.72 里的 −1.44 点、平衡池 +8.59 里的 −4.27 点——**这份伪影不足以把总账搞反**，所以"总数照用"是安全的。但放进**每候选 dev fitness**（搜索每代排序 50 个候选用的那个信号）看就不一样了：两档是 dev 480 题里的 64 题（13.3%），一个候选只要改变这两档的"是否作答"行为，就能凭空移动最多 **13 个点**的 dev 分数，而 dev 的 δ_min 才 6.7 点、全轮的 δ 才 2 点。**这是本票建议"必须登记该轴"的真正理由：不是总账错了，而是每候选的排序信号可以被一条非能力轴拿走 >2× 的 δ。**

## 10. 判定

| 假设 | 判定 | 支撑数字 |
| --- | --- | --- |
| **1. 真实能力差** | **否**（不是负 gap 的成因） | 两臂都作答的子集上 BF16 **+11.13**（`logic/hard`）/ −0.47（`ordering/hard`）；62–76% 的"BF16 失败"是**一个字都没吐**，不是答错 |
| **2. 格式/模板合规伪影** | **字面形式否，广义形式是** | (b) 类只占 0.08% / 0.20% / 0%（**不是"展开/改写"**，且反方向：q0 在对照档展开更多）；但**确实**是"判据在测续写格式而非能力"——76% / 59% 的失败是"没作答"，且**去掉冻结后缀 `Answer:` 后 64.5% → 0.0%** |
| **3. 验证器/gold 缺陷** | **否** | 15,206 条：题面↔规格 0 不一致、gold 复算 0 错、`ordering/hard` 0 多解 0 矛盾 |
| **4. 子模式成分** | **部分**（仅 `logic/hard`） | 负 gap 的 **90% 来自 `gold=4` 子模式**（−51.7 点 × 17.9% 权重）；根因是**答案先验错位**，不是该子模式的题有缺陷；`ordering/hard` 两个 rank 子模式均匀 |

**总判定：混合，但主因是"判据有效性"问题（假设 2 的广义形式）**，机制与假设 2 预期的**方向相反**：不是 BF16 因为更爱展开而被判错，而是 **BF16 在冻结前缀 `Answer:` 上、对这两档的题干直接结束回合（第一个 token 就是 `<|im_end|>`），而判据把"没作答"等价于"答错"**。这条行为：可精确复现（600/600）；不是长度诱发（171 token 的填充题 0/200）；不是 gold/题面问题（0 缺陷）；一去掉那 9 个字符就消失（65.4% → 0.0%）。

### 对 300 代搜索的结论（本票要回答的四问）

1. **要不要改判据？** 不改冻结主轴是**可以接受**的——因为总账（+10.72）方向正确且**偏保守**，主轴仍是"可验证正确率"，改判据会作废已登记的三池分数与 hashes。但必须做两件**零 GPU 成本**的事：
   - **(i) 把"未作答率"上升为逐代上报的独立健康指标**：精确标记是 **GEN 臂的 `gen_n_tokens == 1`**（已在逐题记录里；`--arm both` 天然可得，代价 = dev 每候选 1.47 s → 2.90 s，50 候选/代只多 72 s）。**不要**用 TF 单臂近似——TF 记录里没有"首个 gold 位的 argmax"，`tf_token_hits` 分不出"没作答"和"起手就错"（探针实测 129 条空输出里 77 条 `hits=0`、52 条 `hits=1`）。若不想跑 GEN，可让 `score_taskset.py` **多记一个字段** `tf_first_argmax`（本票探针脚本已经这样做了：它是零成本、纯增量，但要按协议变更走 07/13）。一旦某代优胜者的 `logic/hard` 未作答率显著高于 q0（4.2%），它的 hard 档分数**不可与 q0 同轴比较**，必须按 B 口径（两臂都作答的子集）复核后再决定是否接受。
   - **(ii) 逐 family 门/逐 stratum 归一化不要用 T4 的负 gap**（`logic −6.7`、`ordering −4.1`）：那是平衡池抽样造出来的。若要用，改用 B 口径的正数（`logic +15.53`、`ordering +8.31`）。
2. **要不要删题/删档？** **不要现在删**（会动已验证的三池与 hashes）。而且过滤的可行性是**有限的**：若把"任一臂未作答"的题从生成池剔除，`logic/hard` 只剩 **589 题/侧** → 低于冻结结构需要的 **632 题/侧**（4×316/2），该档就凑不出 267 个 confirm episode；`ordering/hard` 剩 981 题/侧（可行）。所以"删题"这条路的代价是 `logic/hard` 要么降 episode、要么整档出列。
3. **如果非要改题面口径**（推荐留给下一轮、并在此之前单独论证）：把助手侧前缀从 `Answer:` 改成对模型更自然的形式（如带尾空的 `Answer: `，gold 文本改为不带前导空格的 answer），可以按本票 8.3 的结果预期"未作答"归零；但代价是**三池分数需整体重评**（生成池 TF ≈1.5 min/臂 + GEN，见清单 §7 成本表），且要重做 `n_unstable_prefix` 自检（v3 记录过尾随空格的 BPE 前缀不稳定），并重签池 hash。本票**没有**测"带尾空"这一变体，仅测了"完全去掉后缀"。
4. **哪些数字可以继续用？**：全池 `+10.72`（TF）/`+11.18`（GEN）照用；`arith/pct/modulo` 三家族的所有逐 stratum 数字照用（15 档里未作答率最高的是 `modulo/hard` 0.5%，两臂差 ≤0.5 个百分点）；`logic`/`ordering` 家族的逐 family 与逐 stratum 数字**必须**附带 B 口径复核（+15.53 / +8.31，而 hard 两档变为 +11.13 / −0.47）；T4 的两个负 gap（−35.0 / −29.8）**不得**作为"BF16 上界不成立"的证据。

## 14. Part 1 方法：为什么必须重评，以及重评的是什么

上一轮 run 的逐题记录（`~/minicpm5-search/out/formal/records/`，921 个文件）只有 `tf_correct / tf_token_hits / tf_gold_logprob / tf_next_token / tf_next_is_im_end`——**没有首个 gold 位的 argmax**，所以"未作答"既无法从 `tf_token_hits`（分不出"没作答"与"起手就错"，见 §4）也无法从 `tf_next_token`（那是 gold **之后**的 token）还原。因此按本票 §1.3 的同一协议、只加一个字段，用**冻结的终检路径**（`pilot_search.py --confirm-only --resume state.json`，即 15 票跑 final 时用的那条命令）重评。三处改动之外的参数逐字不变（`--linear-backend cutlass`、`--quantization compressed-tensors`、prefix cache 关、`enable_thinking=False`、`Answer:` 前缀、`prompt_logprobs=1/max_tokens=1/temperature=0`）。

**一致性自检（重评必须是"复算"而不是"新测量"）：**

| 量 | 记录值（14/15 票） | 本次重评 | 一致 |
| --- | ---: | ---: | --- |
| confirm：q0 / 中心 item 准确率 | 0.5000 / 0.46111（配对 −3.889 点） | 0.5000 / 0.46111（−3.889） | ✓ |
| final：q0 / 中心 | 0.5000 / 0.4675（mean −0.0325） | 0.5000 / 0.4675（−0.0325） | ✓ |
| final：`logic/hard` / `ordering/hard` 中心 | 0.3500 / 0.2875 | **0.3500 / 0.2875** | ✓ |
| v3 dev：中心 − q0 | −0.42 点（pools-v3 §5） | −0.42 点（0.4958 vs 0.5000） | ✓ |
| v2 dev：中心 − q0 | —（14 票未记） | +1.67 点（0.5167 vs 0.5000） | — |

> 顺带更正一处引用：任务书里"`logic/hard` 0.3375"——记录件里 **0.3375 是 `arith/hard`** 的中心值，`logic/hard` 是 **0.3500**（`final_secondary_analysis.json` 的 `per_stratum_item_acc` 与本次重评逐位一致）。本票所有逐 stratum 数字以记录件为准。

### 15.3 逐代趋势：搜索过程中"不作答"有没有被推动

精确口径只有三个端点（上面的重评）。中间的 17 代只有 `tf_gold_logprob`，因此用一个**代理量**并如实报其质量：

- **代理量标定**（用本票重评的 v2 dev 两臂 960 行、13 个真未作答）：以"gold 平均 logprob 越低越像未作答"计，**AUC = 0.8323**；但**没有可用的绝对阈值**——Youden 最优阈值（−0.96）的假阳率高达 40%（正类只有 13 个、极不平衡），所以**代理值只能用于比较世代之间的相对变化，不能当绝对未作答率**。

| gen00 候选 | −1.2262 | 6.00% | 1.71% | 0.27 / 0.61 |

- **结论：搜索期间没有任何"向不作答漂移"的迹象。**终点（真正要交付的物件）在精确口径下也不高于 q0。上一轮的失败是**真答错**，与 14/15 票"hard 档退化、easy 档改善"的描述一致，而不是本票在 v3 池上发现的那种格式伪影。

### 15.4 对下一轮判断口径的含义

1. **v3 池上"BF16 负 gap"的成因（§1–13）与上一轮 ES 的失败是两件不同的事**：前者是 prompt 后缀诱发的提前结束回合（BF16 专属，量级 10 点），后者是真答错（中心 vs q0，量级 3–4 点）。**不要**用前者去解释后者；也不要因为"上一轮的中心并没有不作答"就认为 §1–13 的风险可以被忽略——风险在于**任何**候选（尤其参照臂/锚点）都可能带这条轴，而不是"这次的中心带了"。
2. 上一轮的中心在 **v3 dev 上 −0.42 点、v3 dev 的未作答率 0.42%**（q0 0.63%）——与 13 票用同一 payload 测到的 −0.42 点逐位一致，可以安全作为 v3 池上的"起点近邻"基线。

### 16.1 `score_taskset.py`

| 改动 | 内容 |
| --- | --- |

| `joint_decomposition(cand, ref)` | 2×2（a/b/c/d）+ `gap=(b−c)/n` + **把 c 拆成 `cand_loss_from_no_answer` 与 `cand_loss_from_wrong`**（§15.2 用的就是它） |

### 16.2 `pilot_search.py`

| 位置 | 改动 |
| --- | --- |
| **启动时（新增）** | `Runner.q0_reference_measure(live)`：把引擎恢复到 q0、在**同一 dev 池**上评一次、**实测并落盘** `records/q0_reference.json`（分数 + 未作答率 + 行集），随后恢复调用前的中心补丁并**断言 `live` 一致**（不一致直接抛错）。之后每一代都与这份**本次运行实测**的基线比，而不是与记忆中的常数比。可用 `--skip-q0-reference` 关掉（关掉后归因不可用，会打日志说明） |
| 每代中心 | `na=` 打进日志；`records/centre_genNN.json`（基线）与 `genNN.json` 的 `center_fitness` 旁挂 `no_answer` + `attribution` |
| 每个候选 | `cand_*.json` 与 `genNN.json` 的 `candidates[]` 增加 `no_answer`（含逐 family）+ `attribution`；日志行加 `na=` |
| **新闸门块** | `genNN.json."no_answer_gate"`：q0 基线、中心的未作答 + 逐桶超出量、**本代最优候选**（按 dev 准确率）的未作答 + 归因、候选群体分布（min/median/max）、以及 `flagged[]` |
| 历史台账 | `history.jsonl` 每行新增 `centre_no_answer`、`centre_no_answer_per_family`、`centre_attribution`、`best_candidate_index`、`best_candidate_no_answer`、`no_answer_flagged` |
| 终检 | `confirm_arms()` 每个臂加 `no_answer`，并额外产出 `arms["attribution_center_vs_q0"]`（中心 vs q0 的归因判定），落盘 + 日志 |
| 汇总 | `summary.json` 增加 `q0_reference`（分数 + 未作答率）与 `no_answer_margin` |
| 新参数 | `--no-answer-margin`（默认 **0.05**）、`--skip-q0-reference` |

**归因规则（机械，写进台账）**：
1. 声称的增益用 `gain_all`（全共同题）；**必须同时报 `gain_both`**（两臂都作答子集）。
2. `gain_all > 0` 而 `gain_both ≤ 0` → **`artifact_dominated`**：增益不成立，是作答模式差异，必须按伪影上报。
3. **任何** arm（中心、本代最优候选）的未作答率**整体**或**任一 family**超过 q0 基线 **> 0.05** → 该代 `flagged`（`no_answer_excess`），无论增益正负；日志打 `NO-ANSWER FLAG`。
4. 未作答率与归因**不参与** fitness、聚合、中心步进与停止判定——它们是并行的健康度与解释性证据。

### 16.3 单测与端到端验证
